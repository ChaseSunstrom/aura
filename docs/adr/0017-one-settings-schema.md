# ADR-0017: One settings schema generates config, the settings UI and the settings docs

- **Status:** Accepted (Phase 2)
- **Reference:** the v2 plan §10 (D17); §1.3

## Context

47 env-var names are read across Python, TS and shell with no single source of truth, so config, the settings UI and the settings docs drift.

## Decision

One settings schema in a new `aura-schema` Pydantic package generates `config.template.yaml`, the settings-UI allow-list (`hermes-settings.json`) and `docs/reference/settings.md`. A CI check fails if any generated artefact drifts from the model. Secrets keep living in `.env`, referenced by name only.

## Consequences

The scattered env reads move into one typed, grouped, described model. `docs/reference/settings.md` is generated by that helper (not by `scripts/gen-docs.py`); this docs set links it. See [ADR-0026](0026-approval-matrix-audit-log.md).
