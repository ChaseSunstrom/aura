# What the pipeline's Python jobs skip

*Research note, 15 November 2026 (T-1449). Measured on commit `0785924`: each
of the sixteen jobs `make ci-jobs` runs was run in its own image, in a fresh
container on a clean clone, with pytest's skip report switched on
(`PYTEST_ADDOPTS=-rs` exported above the job's own lines; nothing else of the
job was changed). The desk column is the same test files run in this
checkout's `.venv`. Nothing in the pipeline was changed by this note.*

A skipped test is green in the pipeline. The three jobs known to skip tests
reported 27, 23 and 5, and nobody had read why. The question here is which of
those skips are right for the image, and which hide a test the job could run.

## The answer

All sixteen jobs were green. Four of them skip tests, **66 in all**; the other
twelve skip none (one of them, `safety-drills`, skips one drill of its own,
counted below the table).

| Kind | Tests | What it means |
|---|---|---|
| By design, skipped on every machine | 21 | a cell of a parametrised table that does not apply, or a live proof that is opt-in |
| Right for the image, run on the desk | 4 | needs Docker, or the host's env file, which a pipeline job must not have |
| **A hole: the pipeline could run it and does not** | **40** | a tool, a package, a user or an image the job lacks |
| Run nowhere | 1 | skipped in the image and on the desk |

So 40 tests that pass on a desk are green in every pipeline without being run.
None of them is known to fail: on the desk the files that hold them pass. The
finding is that the pipeline does not protect them, so a change that breaks
one is found only by whoever next runs `make test` on a machine that has the
missing piece.

## The holes

**H1. Tests that need a Hermes install: 17, and one drill (T-1452).** The thirteen
guard tests drive the approval hook through Hermes's own plugin interface;
the others check the bwrap provider against Hermes's base class, the message
plugin, the gateway's platform list and the plugin manifest against a real
install. The pipeline already has a job in the Hermes image
(`test:plugin-discovery`, 7 seconds), which runs `hermes plugins list` and
nothing else. These tests could run there, or in a second job on that image,
once pytest is installed in it. This is the largest hole and the one nearest
to the approval matrix. What stands in for it today: the smoke job
(`scripts/smoke.sh`) classifies every tool the built image's Hermes exposes
against the matrix and takes one approval round trip, and the matrix itself
(`hermes/plugins/tests/test_matrix.py`) needs no Hermes and runs.

**H2. Tests that need ffmpeg: 12, and one that also needs ffprobe (T-1453).** The
screen-recording tests of the artifacts plugin. The slim Python image has no
ffmpeg; Debian's package pulls a few hundred megabytes on every run of the
job. Options to weigh in the task: the Debian package in that one job, a
static binary fetched and checksum-pinned as `scripts/install-age.sh` does for
`age`, or moving these twelve to a job on the built image, which has both
tools. The media-conversion test is skipped on the desk as well (the desk has
ffmpeg and no ffprobe), so it runs nowhere until one of those lands.

**H3. One install line each: 5 tests (T-1451).** `test:config-render` already runs
`apt-get install curl`; adding `jq` runs two more tests. `python-docx` and
`huggingface_hub` in its pip line run two more. `pillow` in `test:desktop`'s
pip line runs one.

**H4. Tests that are skipped because the job is root: 6 (T-1454).** Each asserts that
a file mode keeps another user out, which root passes through. They are
right to skip as root, and the runner's containers are root. They could run
in the pipeline as a second pytest step under an unprivileged user, on those
three files only.

## What was not looked at

- Jobs with a tag, a service or another job's files (the browser jobs, the
  Android build, the house's own suite where it needs a service, the smoke):
  the tool that made this run cannot reproduce them.
- The Node jobs' own skips (`vitest` reports them differently).
- Whether each skipped test would pass in the image once its piece is there.
  They pass on the desk; the image is a different Python (3.12) and a
  different user.
- A guard against the next silent skip (T-1455). A step that fails the job on a skip
  reason not in a recorded list would have to run in the job itself, since
  the reasons only exist in the image.

## Reproducing it

```bash
python3 scripts/ci-job.py --print test:plugins      # the lines a job runs
# add `export PYTEST_ADDOPTS=-rs` above the job's own lines, run them in the
# image named on the second line, and read the SKIPPED rows at the end
```

`make ci-job JOB=test:plugins` runs the same lines without the report; its
last line carries pytest's count.
